Guidance on this tool

Understand the capture, choose the right analyzer, and investigate network evidence step by step.

HAR + NETLOG

What is Tech Lense Analyzer?

Tech Lense Analyzer is a standalone, browser-based network-forensics tool for examining HAR captures and Chromium / Microsoft Edge NetLog JSON captures. It organizes captured network evidence into requests, domains, headers, cookies, timing, waterfall information, and NetLog events so an engineer can quickly move from a capture to a focused investigation.

Important: The tool analyzes the capture you provide. It does not automatically prove root cause. Use the evidence and the “Confirmed / Probable / Not Established” mindset when drawing conclusions.
HARHTTP ArchiveBest for request / response investigation
NETLOGedge://net-export JSONBest for browser network-stack events
01

When should I use HAR?

Use a HAR when you need to inspect web requests and responses: URL, method, status, headers, cookies, request payloads, response information, timing, initiator and waterfall behavior.

  • HTTP 401 / 403 / 407 / 5xx investigation
  • Redirect and authentication flows
  • API request / response troubleshooting
  • Slow requests and waterfall analysis
  • Cookie, header and parameter inspection
02

When should I use NetLog?

Use a NetLog when you need lower-level browser network-stack evidence that may not be represented completely in a HAR.

  • DNS / socket / connection investigation
  • Proxy and network-stack troubleshooting
  • TLS / connection sequencing
  • Browser network errors
  • Source IDs and event timelines
03

Which file should I collect?

.har → Edge / Chrome DevTools Network export.
.json → Edge edge://net-export / Chromium NetLog dump.

The analyzer detects the structure instead of trusting only the file extension. A JSON file containing log.entries[] is treated as HAR; a JSON file containing the NetLog event structure is treated as NetLog.

QUICK START

How to use the tool

1
Capture the issue

Reproduce the problem while collecting the relevant browser network trace. Keep the capture focused on the scenario you are investigating.

2
Export the evidence

For DevTools, export the Network activity as HAR. For browser network-stack diagnostics, collect a NetLog JSON from edge://net-export.

3
Open Tech Lense Analyzer

Click Choose HAR / NetLog Capture or drag the file onto the drop zone. The file is processed locally in your browser.

4
Confirm the capture type

Check the badge beside the product name. It identifies the detected source as HAR or NetLog.

5
Start broad, then narrow

Review the statistics first, then use Domains, search, status/type filters, Failed, Slow, and the clickable summary cards to focus the Request Explorer.

6
Inspect the evidence

Select a request and review Overview, Headers, Params, Request Body, Response, Timing, Waterfall and NetLog Events where available.

INVESTIGATION WORKFLOW

A practical engineer workflow

Capture→Validate→Filter→Inspect→Correlate→Conclude
Example: If a sign-in scenario shows a 401, do not immediately label it as “authentication is broken.” Inspect the request headers, response headers, redirect chain, timing and surrounding requests. If NetLog is available, correlate the browser network events before deciding what the evidence establishes.
!

Security & privacy

HAR, NetLog, packet captures and ETW exports can contain sensitive information. Depending on how the trace was collected, captures may include cookies, authorization-related data, URLs, query parameters, internal hostnames or other diagnostic information.

  • Use sanitized HAR exports whenever possible.
  • Review captures before sharing them.
  • Do not paste tokens, passwords or secrets into reports.
  • Follow your organization's data-handling requirements.
i

Know the limits

HAR, NetLog, PCAPNG and ETW exports are different evidence formats. A NetLog is an event-based network-stack capture and may not contain the same request/response body information as a HAR.

  • Missing data is not proof that an event did not happen.
  • Browser-local analysis does not make a sensitive capture safe to share.
  • Use packet traces, application logs, server logs or identity logs when the evidence requires them.
