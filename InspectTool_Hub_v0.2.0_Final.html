FEATURE CATALOG · WHAT ITH CAN DO


1. InspectTool Hub at a glance
ITH is a local-first browser-engineering workbench. It offers two mutually exclusive investigation modules—PDF Document Inspector and Certificate & CRL Inspector—plus AI Sense, evidence summaries, reports, feedback/suggestion tools, educational content, and settings for appearance and accessibility.
  • Select one module at a time. When you leave a module with active work, ITH asks before clearing that module.
  • Import progress blocks competing navigation during reads/analysis to reduce accidental interruptions.
  • Work is designed to remain in the current browser tab unless you explicitly configure remote AI and approve a summarized request, or open an external knowledge link.


2. PDF Document Inspector · identity and structure
Inspect local PDF bytes and visible structural markers. Available sections cover document information and visible XMP metadata, imported-file name/size/type, SHA-256 where supported, PDF header/catalog version indicators, page dimensions and page boxes, rotation/UserUnit, font-object inventory, object types/counts, cross-reference/trailer data, compressed object streams and incremental-revision markers.
  • Review links, annotations/forms, images and multimedia markers, attachments/embedded files, JavaScript/open-action/launch markers, hidden-property indicators and unresolved/malformed structure warnings where the parser can see them.
  • Review encryption and encoded permission flags, signature-field markers, ByteRange layout and covered-byte digest evidence, and embedded signer-certificate candidates where visible.
  • Use per-section Collapse/Restore controls to focus on relevant findings. Filtered diagnostic reports and JSON/TXT exports are available in the inspector.
Interpretation: indicators are structural evidence. They do not prove maliciousness, merging, rendering correctness, permission enforcement or signature validity by themselves.


3. PDF compatibility and reader hand-off
Review PDF compatibility against the available legacy/current profiles, see the limitations of the installed browser viewer, open the original in a new tab, save an untouched copy, and print/save an inspection report as PDF. Reader-compatibility commands can prepare a separate testing workflow for approved utilities such as qpdf or Ghostscript.
  • Record the actual browser/reader version and policies during reader-to-reader comparisons.
  • A compatibility profile is a diagnostic comparison, not a switch to a historical rendering engine.
  • Rewriting, optimizing, repairing or converting a signed PDF can change bytes and may invalidate signatures; preserve the original.


4. Certificate & CRL Inspector · X.509 and PKI
Import .crt/.cer/.pem/.der certificates, PEM chains, .crl files and supported CMS/PKCS#7 bundles. The inspector surfaces Subject and Issuer, serial, validity, SAN, public-key and signature-algorithm fields, SHA-1/SHA-256 fingerprints, Basic Constraints, Key Usage/EKU, Certificate Policies, AIA, OCSP/CRL endpoints, Authority Key ID and Subject Key ID, plus CRL issuer/update fields and visible revoked entries.
  • Generate OpenSSL commands locally for a URL/hostname/IP workflow; run them in the target environment and paste the resulting PEM chain. ITH does not silently probe remote hosts.
  • Use provider and standards links for chain installation, certificate renewal, revocation education and independent server checks.
  • Compare external public CA and internal enterprise PKI scenarios, including proxy/TLS inspection, user/device trust stores, Intune/GPO deployment and Edge/WebView2 behavior.
Interpretation: parsing certificate fields is not the same as building a trust chain, checking hostname policy, verifying certificate/CRL signatures or confirming real-time revocation status.


5. AI Sense · investigation assistance
AI Sense is the investigation sidecar. It provides local deterministic guidance, a conversation workspace, evidence context, report actions, feedback and suggestions, and configurable optional AI provider/model presets.
  • Quick Investigation Runbooks include deep diagnostic review, security/signature review, reader compatibility, hidden/active content, certificate/trust path, remediation checklist, customer-ready summary, engineering escalation, reproduction plan, leadership brief and support case/ticket draft.
  • Runbooks can return general checklists without a file; when parsed evidence is available, the assistant can include a minimized evidence summary and must distinguish observed facts, hypotheses and missing evidence.
  • Local Expert Mode does not require an API key. Remote AI requests require a configured endpoint/key and a confirmation step. Sanitization is a best-effort control, not a guarantee that every sensitive value is removed.
  • The conversation can be expanded into a focus-mode panel. Use settings to choose supported provider/model presets and inspect the data-handling notice.


6. Evidence, reports, exports and feedback
Use the Evidence area for a structured capture of current parser observations; review report-oriented summaries, copy or export available findings, and save local snapshots. Feedback can be recorded locally or exported as JSON. Suggestions create a draft addressed to the configured fixed recipient and do not send mail automatically.
  • Exports may contain filenames, metadata, subject names, email addresses, hostnames, internal URLs, file paths or certificate identifiers. Review before sharing.
  • Retain original inputs separately if evidence integrity matters. A matching hash identifies bytes; it is not by itself a full chain-of-custody control.
  • Where local browser storage is unavailable or restricted, some preferences/history may not persist.


7. Knowledge Hub and browser-engineering learning path
Use the built-in learning path and knowledge links for Microsoft Edge PDF behavior and policies, PDF standards, X.509 / RFC 5280, OCSP / RFC 6960, Certificate Transparency / RFC 9162, and Edge certificate verification. The Certificate Authority tools hub links to GoDaddy, DigiCert, GlobalSign, Google Trust Services and Let's Encrypt / ISRG resources.
  • Learn about browser PDF handling, content type/disposition, signatures, internal/public CA chains, hostname matching, revocation endpoints and enterprise trust context.
  • Use authoritative external links for independent checks; opening a link may disclose the target URL to the external site.


8. Appearance, accessibility and workspace controls
ITH supports Modern/Classic palettes, Light/Dark mode, Smaller/Default/Larger text settings, collapsible forensic information sections, a compact/expanded AI Sense side panel with splitter, module cards, and a full-screen AI Sense conversation view. Use the About Tool guide from the top header or AI Sense sidebar.
  • Prefer Default or Larger text when reviewing dense evidence tables; use Collapse/Restore to keep the report focused.
  • The import overlay indicates the current stage while parser controls are locked during active processing.
  • On narrow screens, panels and diagnostic grids reflow; if a control is clipped, widen the window or restore default text size.


9. Privacy, security boundaries and unsupported claims
ITH is a diagnostic aid, not a security verdict or a replacement for platform-aware validators. Local parsing is preferred. Remote AI is optional and consent-gated; original document bytes are not intentionally sent by the AI summary workflow.
  • Not fully provided by this standalone HTML: complete PDF rendering/conformance validation, OCR of scanned-only text, decryption of protected content, full CMS/PAdES cryptographic signature validation, complete certificate-chain/trust-store validation, reliable live OCSP/CRL probing, and server-backed case database/chain-of-custody workflows.
  • Encrypted/object-stream-heavy or malformed files may expose only partial structure. Some objects may be compressed or beyond the parser’s current support.
  • Always corroborate high-impact conclusions with the target browser/OS, supported PDF reader, enterprise policy evidence and approved cryptographic utilities.


10. Enterprise v0.2.0 Upgrades · Standards, WebCrypto & DevSecOps
ITH v0.2.0 adds standards-driven enterprise diagnostics across both modules without sacrificing local-first privacy:
  • ISO PDF Standards & Accessibility Matrix: Evaluates PDF/A (ISO 19005), PDF/UA (ISO 14289), PDF/X (ISO 15930), Tagged PDF (/MarkInfo & /StructTreeRoot), natural language (/Lang), and PAdES Long-Term Validation (/DSS Document Security Store, /DocTimeStamp, /DocMDP).
  • Visual ByteRange Map & Object Hex/ASCII Inspector: Proportional visual map of signed vs. unsigned byte ranges plus an interactive 16-byte Hex + ASCII stream/object dump inspector.
  • WebCrypto Chain/CRL Signature Verification & Edge RFC 5280 Linter: Cryptographically verifies RSA and ECDSA certificate chains and CRLs in-browser via WebCrypto, decodes Certificate Transparency SCT lists (1.3.6.1.4.1.11129.2.4.2) and OCSP Must-Staple (1.3.6.1.5.5.7.1.24), cross-checks certificate serials against loaded CRLs, and lints against Microsoft Edge 112+ strict RFC 5280 verifier rules (Chromium issues 1453441 & 1457348, LDAP CRL rejection).
  • SARIF 2.1.0 & Command Palette: Export findings as OASIS SARIF 2.1.0 JSON for SIEM/DevSecOps pipelines, or press Ctrl+K / Cmd+K for instant keyboard navigation and 1-click sample evidence generation.


DETAILED GUIDANCE & TUTORIALS

 
1. PDF parser workflow
  1. Choose a PDF file. The tool reads bytes locally and reports file details and hash if Web Crypto is available.
  2. Review document metadata and PDF version indicators. Producer and Creator are metadata claims, not proof of the software currently used to open the file.
  3. Review structure: page/object counts, xref/trailer/revision markers, links, image objects, attachments, scripts/actions, forms and hidden-property indicators.
  4. Review encryption permission flags and signature fields. Open the original in Edge, Adobe Acrobat/Reader or Nitro to confirm actual rendering and digital-signature status.
Important: PDF incremental updates may create multiple xref/EOF markers. This is not conclusive evidence that a PDF was merged or tampered with.

 
2. PDF rendering in browsers
When navigation returns a PDF MIME type or a download disposition, browser behavior depends on response headers, policies, user settings and the built-in/registered PDF handler. The viewer parses page trees, fonts, images, annotations, forms and actions; security settings may block active content or external actions.
  • Capture response headers: Content-Type, Content-Disposition, redirects and authentication outcomes.
  • Compare local file vs HTTPS URL, download vs inline, managed vs unmanaged profile, and browser version.
  • Check document encryption, malformed xref/trailer, missing fonts, embedded files, JavaScript/open actions, form/XFA content and signatures.
  • For suspected signature problems, validate in the supported reader and capture signature-panel details; structural indicators alone do not validate signature integrity.
  • Check AlwaysOpenPdfExternally when PDFs download instead of opening inline.
  • Check PDFSecureMode for certificate-based signature validation in Edge's native PDF reader. Microsoft documents behavior changes by Edge release (including the Windows default beginning in Edge 154) and reader mode.
  • Per Microsoft Learn, NewPDFReaderEnabled is deprecated starting in Edge 156 and planned to become obsolete in Edge 162 now that the Adobe Acrobat-powered built-in PDF reader is standard; PDFSecureMode is enabled by default on Windows starting in Edge 154.
References: Edge PDF reader · AlwaysOpenPdfExternally · PDFSecureMode.

 
3. Certificate parser workflow
  1. Import .crt/.cer/.pem/.der or .crl, or paste the PEM chain.
  2. Review Subject, Issuer, validity, serial, SAN, public-key algorithm and size, signature algorithm and SHA-1/SHA-256 fingerprints.
  3. Review Basic Constraints, Key Usage, Extended Key Usage, SKI/AKI, AIA/OCSP, CRL distribution points and Certificate Policies.
  4. For a URL/IP, generate the OpenSSL command locally, run it on a system with OpenSSL, then paste the complete PEM output. The tool intentionally does not send the hostname to a third party.
Command for common TLS ports: openssl s_client -connect host:443 -servername host -showcerts. For IP-only targets, use the IP for -connect and the DNS name for -servername when SNI is required.

 
4. External vs internal certificates in Edge
External HTTPS certificates typically chain to a publicly trusted root and must match the site hostname and validity requirements. Internal services can use enterprise private CAs, but the correct root/intermediate must be installed and trusted in the relevant device/user context. A TLS inspection proxy can substitute a certificate issued by an organization-managed CA.
  • Check Subject Alternative Name (SAN) before falling back to legacy Common Name assumptions.
  • Check Server Authentication EKU, Key Usage, expiry, chain completeness, name constraints and path constraints.
  • Check whether AIA fetching, OCSP or CRL retrieval is reachable through proxy/firewall rules.
  • Compare Edge, WebView2 host app and OS store behavior on the same managed device; trust paths may differ by platform and browser version.
  • Microsoft documents that Edge 112+ on Windows/macOS uses a browser-shipped default trust list and verifier, while continuing to consider locally installed enterprise roots. Confirm the applicable browser version and policies.
References: Microsoft Edge TLS certificate verification · RFC 5280.

 
5. Enterprise deployment triage
  • Intune / MDM: confirm device/user assignment, policy sync, certificate profile deployment, and device vs user store context.
  • Group Policy: collect gpresult /h gpresult.html, verify applied policies and compare expected registry policy values.
  • Windows certificate store: check Current User and Local Computer Personal/Trusted Root/Intermediate stores as applicable.
  • Networking: correlate proxy/PAC, TLS inspection, DNS, TLS negotiation, SNI and HTTP response evidence.
  • WebView2: record runtime version, host app, profile/data folder, policy environment and whether standalone Edge reproduces the issue.

 
6. PDF FORENSIC LAB feature mapping
ITH v0.2.0 brings browser-safe counterparts of the earlier PDF FORENSIC LAB V5.0 modules into the local inspector: SHA-256 document identity, PDF properties and page forensics, font inventory, encryption/permission interpretation, signature-marker and ByteRange coverage review, embedded X.509 certificate candidate extraction, JavaScript/action markers, embedded-file and object-tree inventories, heuristic risk findings, report export, and a local case/evidence audit ledger.
The original Python project uses PyMuPDF, a dedicated signature-forensics module (and a separate signer-validation path), JavaScript/embedded/object-tree/certificate modules, a risk engine, HTML/PDF report generation, SQLite case management, file-system evidence storage, and FastAPI case/evidence/audit routes. These backend-native features are mapped into the browser UI where feasible; they have not been silently represented as imported Python execution.
Not equivalently implemented in the standalone HTML: full PyMuPDF page-content extraction, pyHanko/CMS signature verification, private trust-store access, complete PDF rendering/conformance validation, server-backed SQLite/FastAPI case storage, and formal chain-of-custody controls. For production investigations, pair ITH with an approved PDF Forensic Lab backend or external validators.

 
7. Certificate Authority tool and knowledge hub
The Certificate & PKI module links to official resources from GoDaddy, DigiCert, GlobalSign, Let's Encrypt / ISRG, Google Trust Services, RFC 5280, RFC 6960, RFC 9162, and Microsoft Edge certificate-verification guidance. Use provider tools for independent server-chain checks, CSR validation, issuer/intermediate retrieval, issuance/renewal guidance, and revocation education.
Practical workflow: (1) collect the actual server chain from the affected client network using OpenSSL or an approved capture method; (2) inspect SAN, validity, EKU/KU, AKI/SKI and AIA/CRL endpoints in ITH; (3) verify chain and status using an independent platform-aware tool; (4) reproduce in the target Edge build and system context; (5) report the specific distinction between expired, hostname mismatch, incomplete chain, untrusted root, retrieval failure, and a confirmed revoked status.
External checking tools are optional links only. ITH does not automatically transmit hostnames, certificates, PDF files, or case notes to a CA.

 
8. Performance, privacy and limitations
PDF structure and X.509/CRL fields are parsed locally. Large or heavily compressed PDFs may hide content in object streams, and encrypted documents may expose only limited structural information until opened with valid credentials. This prototype does not decrypt content, render PDF pages, verify CMS/PAdES signatures, build a complete trust path, or check real-time revocation.
References: Edge TLS certificate verification · RFC 5280.
Keep customer documents/certificates under approved handling rules. Exported JSON/TXT may contain subject names, email addresses, internal URLs, server names, file paths and other sensitive metadata.
